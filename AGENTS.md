# XmaxSDK React Native Engineering Conventions

Read README.md, package.json, and the public source declarations first. The current implementation provides camera input, image input, external native video and PCM audio input, and storage. Report support only when the capability has been implemented and validated at the claimed level; distinguish compilation from device validation.

- TypeScript owns business logic. Align Core/Service/Media/Stream/Render/Foundation responsibilities and key names with the iOS SDK. The reference checkout is `/Users/xmax.ai/dev/Xmax/iOS/XmaxSDK`; it is not a runtime, build, or publishing dependency.
- XmaxRealtimeFactory owns concrete component creation, callback wiring, and ordered resource cleanup. XmaxRealtimeManager coordinates public operations through the shared components and controller/service interfaces. Keep XmaxRealtimeLifecycleManager responsible for operation admission, cancellation, state commitment, and termination; route runtime failures through XmaxRealtimeErrorManager.
- Foundation owns RTC platform and room adapters, cancellable FIFO engine leases, media permissions, storage transport contracts, and private encoded-data staging. RtcManager coordinates waits and normalized events through RtcPlatform, RtcRoom, and RtcEngineManaging; CameraController directly owns PermissionManaging; native JSON and numeric account mapping stay within Agora adapters.
- MediaController owns camera, image, external-source, and interaction controllers. Rendering binds streams and tracks through VideoRenderBinding and VideoRenderRegistry. Keep native RTC operations behind RtcManaging and business services behind their service contracts. Support component injection without importing concrete implementations into consumers solely for type declarations.
- XmaxRealtimeVideo displays one local or remote track through track. XmaxRealtimeDualVideo overlays localTrack and remoteTrack, keeping preview mounted and showing confirmed remote output after its first rendered frame. remoteVideoFadeInDuration defaults to 0.3 seconds; nonpositive or nonfinite values disable animation, and changes apply to the next fade-in. Stop animations before native hiding or view release. XLab explicitly uses zero to retain immediate switching. Do not restore XmaxVideo or dual-track props on XmaxRealtimeVideo.
- Preserve iOS public API names and return semantics, including `currentState`, `sessionID`, `taskID`, `fileURL`, `progress`, `set*Listener`, `stopLocalCameraStream`, and `stopLocalImageStream`. Do not restore the obsolete `addListener`, `getState`, `getAudioVolumes`, `stopLocalStream`, `dispose`, or `XmaxMediaService` APIs.
- Public XmaxConfiguration selects service roots through environment; do not expose a baseURL override.
- XmaxClient returns the public XmaxRealtimeManaging, XmaxStorageManaging, and MediaServicing interfaces. Concrete managers remain internal. Map Swift argument labels to TypeScript options objects and asynchronous methods to Promises; retain synchronous factories and size calculations.
- Image input accepts file URLs or encoded imageData bytes. Storage uploads accept file URLs or encoded data with filename and MIME type. Snapshot bytes at the public call boundary and remove temporary files on success, cancellation, and failure. Both native platforms submit fixed-size image frames. Do not use dummy capture. Local image preview uses RN Image. RTC transport uses Agora 4.6.4. Generation waits for target-room publication and a fresh decoded result frame through a native one-shot observer, independently of mounted views. Subscribe result audio only after frame readiness; input SEI and SEI task confirmation are not used. Frame interpolation, local video-file generation, Web, Expo Go, per-frame JS output, and a turnkey SDK recording API are not implemented.
- External capture uses createExternalVideoStream / stopExternalVideoStream with an app-owned RealtimeExternalVideoSource. TypeScript owns source lifecycle and hands its expiring nativeHandle to a native producer. Native RealtimeExternalFrameSink.find accepts copied upright video and PCM directly; never shuttle raw frames through JavaScript. Source dimensions and cadence remain stable; timestamps share a monotonic timeline. Disconnect preserves preview; stop, close, failures, and background release invalidate the native sink before engine destruction. XLab selects a file and decodes it in app-owned native code, independently of the SDK local video-file API.
- Remote media output uses setRemoteMediaFrameListener with an app-owned RealtimeMediaFrameConsumer native handle. TypeScript registers and serializes binding changes; Swift/Kotlin deliver owned result-user PCM and video on bounded serial native queues (256 packets, 32 MiB). Never emit per-frame payloads to JS. Preserve stream identity across listener replacement, create a new identity for each result binding, normalize audio by sample count on the native rendering clock, and mark gaps and format changes. Remove queued output on stop, disconnect, listener replacement, background release, and engine destruction without changing audio subscriptions or volume. XLab camera and external capture examples encode remote output to MP4 using app-owned native recorders and save to Photos or MediaStore. Finalize recordings on generation stop, backgrounding, file replacement, and exit; never transfer raw media through JavaScript.
- The current models are `x2.1.1-preview-cn` and `x2.1.1-preview-us`, supporting 1024×1920 and 1920×1024 at 30 fps. Keep the reference checkout authoritative for authorized model synchronizations. Model capabilities and environment routing are separate. Both realtime and storage use `environment`: global realtime uses `api.xmax.ai`, while global storage uses `api.xmax.cloud`. The legacy RealtimeCameraPreset cases remain declared; current model formats have no corresponding preset. Use supportedVideoFormats for available capture choices. Local image dimensions are aligned to 4 within 200000–2100000 pixels, upscaling small images as needed. Camera format updates require Ready preview and a disconnected session, preserving stream and track identity. Transport quality changes do not alter capture metadata. Uplink quality tiers use 4-pixel alignment and retain the model minimum input area. Downlink signaling uses a 500 kbps floor and a size-based maximum clamped to 500–10000 kbps. Manual quality changes require Generating and preserve the configured adaptation policy. isAdaptiveQualityEnabled defaults to true; false starts at L1 without reading or writing history. Keep source media dimensions, generation canvas dimensions, and adaptive return dimensions distinct. Record successfully applied initial quality only after generation becomes ready, including the initial stabilization window after camera-triggered task restarts. Automatic adaptation starts after generation readiness. Trajectory coordinates are normalized source-media coordinates in `[0, 1]`; never map touches using the generation canvas.
- The iOS implementation uses Swift 6. Objective-C++ is limited to thin RN Codegen / TurboModule adapters. Document Swift declarations with `///` and follow the Swift formatter configuration. TurboModule initialization can occur on the JS thread; read UIKit state by explicitly dispatching to the main queue, never by assuming isolation with `assumeIsolated`.
- Native code provides the required file operations, image frame ingress, permissions, background resource release, and display events. Do not duplicate HTTP or generation business logic in Swift or Kotlin. Keep vendor types within Foundation and out of the public API.
- The primary example lives in Example/XLab. Its UI and interaction model follow the current UIKit XLab reference. Resolve its service environment from the interface language: Chinese uses China, English uses Global. Offer all SDK models independently of language or environment, and preserve the selected model when the language changes. Keep separate persisted regional keys and SDK bitrate defaults; do not add manual endpoint or bitrate panels. Face restoration follows clothx reference selection, with no separate switch; touch animation submits an empty prompt. Keep the supported camera actions vertical on the right and file actions horizontal above preview. File reselection waits for cleanup, preserves reference controls, and resumes generation only when it was requested before replacement. Statistics show measured network quality and scroll within the preview bounds. Expo installation validation and config plugins remain deferred; do not create an ExpoHost or require Expo runtime for ordinary RN consumers.
- A new generation request replaces pending generation and waits for predecessor cleanup; other foreground operation kinds remain exclusive. Foreground work waits for active background quality configuration. Final operation states are delivered only after releasing operation admission so listeners can submit new work. Repeated explicit connect calls reject; the generation convenience overload may reuse an existing connection. Disconnecting and closing cancel queued generation requests; closing remains idempotent. Reject stale lifecycle events, reclaim sessions allocated after cancellation, and keep independent storage tasks unaffected by realtime close.
- Start, condition-update, and stop room signals discard unsent messages and remaining unsent fragments before submission; target-size changes retain ordering, and tracks coalesce by task.
- RTC room admission uses a 15-second deadline. API roots require HTTPS and request paths are trimmed and constrained to the configured host. Storage timeouts belong to the API and native transfer layers; do not add a separate service-wide transfer deadline. Sanitize encoded-upload filenames using the same rules as file uploads. Read upload display dimensions through MediaFileMetadataManaging only for enabled diagnostics; metadata failure must not fail a transfer.
- When dependencies change, maintain the lockfile and validate installation. Consumers must not depend on manual node_modules patches or sibling checkouts. Expand the support matrix only after actual validation.
- Test API contracts, signaling and dimension fixtures, and resource lifecycle races relevant to the change. Media and background behavior require device validation. Run appropriate checks without adding redundant tests for documentation-only edits.
- Use [docs/sdk-comment-and-formatting-guidelines.md](docs/sdk-comment-and-formatting-guidelines.md) as the single source of truth for documentation language, comment syntax, coverage, formatting, file headers, and validation requirements. Do not maintain a separate summary of those rules here.
- Example/XLab retains its existing function spacing and JSDoc conventions. Document important screens, components, hooks, and data boundaries. Keep Hook order unchanged during formatting. Do not describe UI-only interactions as connected business features. Example-wide documentation migration requires explicit scope; this SDK documentation guide does not automatically expand it.
- Logging uses the global business/performance bitmask and native OSLog/Logcat output. The latest client also sets log-detail language from its environment. Startup timing records only observed session, join, publication, and first-frame readiness stages, without treating cancellation as failure. Do not log raw responses, credentials, prompts, or native exception bodies. Read only statistics supported by the current platform. Do not restore temporary per-frame diagnostics.
- Use English Conventional Commits and validate the affected scope before committing. Do not commit local configuration or credentials. Branches follow `main`, `develop`, and `feature/<developer>-v<version>`; use the current branch as the source of truth for its version.
- Keep internal development documents untracked under `docs/`, and public README assets tracked under `materials/`. Ignoring a path does not untrack existing files. Preserve the standard source filename, author, RN repository URL, and copyright header.
