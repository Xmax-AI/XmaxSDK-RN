# XmaxSDK React Native Engineering Conventions

Read README.md, package.json, and the public source declarations first. The current implementation provides camera input, image input, and storage. Report support only when the capability has been implemented and validated at the claimed level; distinguish compilation from device validation.

- TypeScript owns business logic. Align Core/Service/Media/Stream/Render/Foundation responsibilities and key names with the iOS SDK. The reference checkout is `/Users/xmax.ai/dev/Xmax/iOS/XmaxSDK`; it is not a runtime, build, or publishing dependency.
- Preserve iOS public API names and return semantics, including `currentState`, `sessionID`, `taskID`, `fileURL`, `progress`, `set*Listener`, `stopLocalCameraStream`, and `stopLocalImageStream`. Do not restore the obsolete `addListener`, `getState`, `getAudioVolumes`, `stopLocalStream`, `dispose`, or `XmaxMediaService` APIs.
- XmaxClient returns the public XmaxRealtimeManaging, XmaxStorageManaging, and MediaServicing interfaces. Concrete managers remain internal. Map Swift argument labels to TypeScript options objects and asynchronous methods to Promises; retain synchronous factories and size calculations.
- Both native platforms submit fixed-size image frames. Do not use dummy capture. Local image preview uses RN Image. RTC transport uses Agora 4.6.4. Generation waits for the target room and result account to publish video; input SEI and SEI task confirmation are not used. Frame interpolation, local video-file generation, Web, Expo Go, per-frame JS output, and recording are not implemented.
- The current RN model is `x2.1`; consult the reference checkout before an authorized model synchronization because iOS models may have changed. Model capabilities and environment routing are separate. Both realtime and storage use `environment`: global realtime uses `api.xmax.ai`, while global storage uses `api.xmax.cloud`. Five RealtimeCameraPreset values are implemented in RN. Camera format updates require Ready preview and a disconnected session, preserving stream and track identity. Transport quality changes do not alter capture metadata. Manual quality changes require Generating and retain automatic adaptation. Keep source media dimensions, generation canvas dimensions, and adaptive return dimensions distinct. Trajectory coordinates are normalized media coordinates in `[0, 1]`.
- The iOS implementation uses Swift 6. Objective-C++ is limited to thin RN Codegen / TurboModule adapters. Document Swift declarations with `///` and follow the Swift formatter configuration. TurboModule initialization can occur on the JS thread; read UIKit state by explicitly dispatching to the main queue, never by assuming isolation with `assumeIsolated`.
- Native code provides the required file operations, image frame ingress, permissions, background resource release, and display events. Do not duplicate HTTP or generation business logic in Swift or Kotlin. Keep vendor types within Foundation and out of the public API.
- The primary example lives in Example/XLab. Its UI and interaction model follow the current UIKit XLab reference. Expo installation validation and config plugins remain deferred; do not create an ExpoHost or require Expo runtime for ordinary RN consumers.
- Closing must interrupt pending operations and remain idempotent. Reject stale lifecycle events, reclaim sessions allocated after cancellation, and keep independent storage tasks unaffected by realtime close.
- When dependencies change, maintain the lockfile and validate installation. Consumers must not depend on manual node_modules patches or sibling checkouts. Expand the support matrix only after actual validation.
- Test API contracts, signaling and dimension fixtures, and resource lifecycle races relevant to the change. Media and background behavior require device validation. Run appropriate checks without adding redundant tests for documentation-only edits.
- Use [docs/sdk-comment-and-formatting-guidelines.md](docs/sdk-comment-and-formatting-guidelines.md) as the single source of truth for documentation language, comment syntax, coverage, formatting, file headers, and validation requirements. Do not maintain a separate summary of those rules here.
- Example/XLab retains its existing function spacing and JSDoc conventions. Document important screens, components, hooks, and data boundaries. Keep Hook order unchanged during formatting. Do not describe UI-only interactions as connected business features. Example-wide documentation migration requires explicit scope; this SDK documentation guide does not automatically expand it.
- Logging uses the global business/performance bitmask and native OSLog/Logcat output. Do not log raw responses, credentials, prompts, or native exception bodies. Read only statistics supported by the current platform. Do not restore temporary per-frame diagnostics.
- Use English Conventional Commits and validate the affected scope before committing. Do not commit local configuration or credentials. Branches follow `main`, `develop`, and `feature/<developer>-v<version>`; use the current branch as the source of truth for its version.
- Keep internal development documents untracked under `docs/`, and public README assets tracked under `materials/`. Ignoring a path does not untrack existing files. Preserve the standard source filename, author, RN repository URL, and copyright header.
